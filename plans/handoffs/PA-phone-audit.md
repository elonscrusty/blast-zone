# PA Phone audit + lobby walking
- Cause of carter's pile-up: Roblox starts a landscape game upright, turns it a moment later. `UiKit.place` laid the lobby out for the upright shape and only re-ran if the camera's size changed (and never connected at all when there was no camera yet). Now every placed piece is redone when its parent's size changes, the camera's size changes, or the camera is replaced.
- The Studio emulator has no notch, no Roblox top bar and never turns, so it looked clean. `src/client/Ui/DeviceZones.luau` holds what a real phone adds (top bar 58 dp, menu + chat buttons 112 dp wide top left, notch up to 64 dp).
- `tests/phone_audit.test.luau`: 13 phones (SE to iPad Pro, carter's 852x393 with notch), per ScreenGui frame (full / safe / core), phases lobby, fight, pick chips, spectate, both hands. Fails on overlap, a piece under Roblox's buttons or the notch, or a thumb target under 44 dp (lobby 38, it shrinks on 16:9 phones).
- Every ScreenGui in src/client must be in its GUIS table with the frame the code really uses, so new UI cannot skip the audit. Adding UI: put the rect in Ui/ScreenMap (or Hud/Layout), use Components.screen, add the piece to its phase in the test.
- Moved to clear Roblox's buttons and each other: HUD vitals (x 116), warning + moment banner, zone arrow (top, right of the status chip), WINS/ELIMS/GAMES card (Ui/ScreenMap.statsCard), bots banner, map vote (narrower), wallet bar (note now left of the bar, shorter), look picker (ScreenMap.lookPicker, same shrink as the rest), save strip (13% tall, text starts right of Roblox's buttons). MatchFlow is now a safe-area screen; results colour moved to MatchFlowBackdrop (full bleed).
- Walking: lobby phases Waiting and Countdown let stick, WASD and pad move you (`HudModel.walkOn`, `Controls.setWalking`); aiming, firing, slide, reload and camera turn stay off. Phone: a whole-screen catcher under every button, the ring shows only under the thumb. Server unchanged: it still decides positions (MoveGuard) and shots.
- `Ui/CoreGuiSystem` hides Roblox's player list, backpack, emote menu and health bar (we have our own); menu + chat stay.
- Also: EMOTE button text fits its circle (was cut to "EMOT").
- Proof: Lune 1383 pass, StyLua clean, rojo build ok, luau-lsp strict analysis shows no new type errors. Selene runs in CI (could not fetch its Roblox std here).
- Not proven: carter's real phone. Ask for one lobby + one fight screenshot after the batch. Known gaps: text width inside buttons (Roblox fonts) is not measured; results screen contents, modal panels and upgrade cards have their own tests, not this one.
